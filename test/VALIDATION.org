The example was changed to call the original resolver while dynamically binding the original callback, preserving the client's default behavior.

A client session validated diagnostic overlays with the final example and all three real modes. * Project roots and ambiguous suffixes (2026-11-01)

~surge-project-roots~ was added to restrict automatic recognition of ordinary ~.conf~ and ~.dconf~ files to user-declared Surge workspaces.  ~.sgconf~, ~.sgmodule~, and the exact filename ~Surge.conf~ remain globally recognized.  ~surge-project-root~ uses real paths and chooses the longest matching root; a symlink inside a project that points outside it is not recognized as a Surge project file.

The lsp-bridge example now gives the same Surge root priority, delegating to the project-root callback that existed before the example was loaded when a file is outside those directories.  If the original callback is nil, lsp-bridge's ~.dir-locals.el~ fallback is preserved.  Both JSON examples declare ~languageIds~ for ordinary suffixes, and the optional watcher example includes ~**/*.sgconf~.

A behavioral probe in the running Emacs confirmed that project-local ~.conf~ and ~.dconf~ files enter ~surge-conf-mode~, a ~.conf~ file outside the project remains in ~conf-unix-mode~, and the lsp-bridge callback returns the configured Surge root.  The probe only created and removed a temporary directory; it did not start a language-server process.
